# Compute Hub (WebProject-HardTasks)

Веб-застосунок для виконання трудомістких обчислювальних задач з балансуванням
навантаження між кількома application-серверами.

## Ідея
Користувач реєструється, ставить задачу (розв'язання СЛАР методом Гауса або
обробка зображення згорткою), бачить прогрес, чергу з приблизним часом
очікування, може скасувати задачу й переглянути історію. Запити розподіляє
nginx між кількома app-серверами, задачі виконують воркери на різних серверах.

## Можливості
- Задачі: СЛАР (метод Гауса з вибором головного елемента), фільтри зображень (розмиття, різкість, контури)
- Прогрес у реальному часі, скасування, історія задач
- Черга з орієнтовним часом очікування
- Авторизація (bcrypt + JWT в httpOnly cookie), HTTPS
- Load balancer (nginx), мінімум 2 app-сервери
- Автоскейлінг контейнерів з верхнім лімітом
- Адмін-панель моніторингу (/admin)
- Ліміти складності задач і кількості активних задач на користувача

## Архітектура
    Клієнт -> nginx (HTTPS) -> app-1..N (FastAPI + воркер) -> PostgreSQL
                                   ^
                    autoscaler (Docker SDK) стежить за чергою

- Задачі й черга зберігаються в PostgreSQL. Воркер бере задачу через
  `SELECT ... FOR UPDATE SKIP LOCKED`, тому кожна задача виконується рівно одним сервером.
- Воркер пише прогрес кожні ~0.5 с; та сама операція повертає прапор скасування.
- Воркери шлють heartbeat у таблицю `workers`. Якщо контейнер зупинено,
  його задачі автоматично повертаються в чергу.
- nginx резолвить ім'я `app` через Docker DNS (кожні 5 с), тому нові
  контейнери автоскейлера підхоплюються без перезапуску.
- Відповідь кожного сервера містить заголовок `X-Served-By` (видно балансування).
- Орієнтовний час очікування = середня тривалість останніх задач × позиція в черзі / кількість воркерів.

## Запуск
    cp .env.example .env          # змінити паролі й SECRET_KEY
    bash scripts/gen_cert.sh      # самопідписаний сертифікат
    docker compose up --build

Відкрити https://localhost (прийняти самопідписаний сертифікат).
Адмін: логін/пароль з `.env` (ADMIN_USERNAME / ADMIN_PASSWORD), сторінка https://localhost/admin

## Масштабування
Вручну: `docker compose up --scale app=3`.
Автоматично: сервіс `autoscaler` додає сервер, коли в черзі більше
`SCALE_UP_QUEUE` задач на сервер (до `MAX_APPS`), і прибирає зайві після
`SCALE_DOWN_IDLE` секунд простою (не нижче `MIN_APPS`).

## Ліміти
- СЛАР: n ≤ 1500
- Зображення: ≤ 4 МП, ≤ 5 МБ, ядро 3-21, до 5 проходів
- Не більше 3 активних задач на користувача

## API
| Метод | Шлях | Опис |
|-------|------|------|
| POST | /api/register, /api/login, /api/logout | авторизація |
| GET | /api/me | поточний користувач |
| POST | /api/tasks/linear | нова задача СЛАР `{n}` |
| POST | /api/tasks/image | нова задача (multipart: file, filter, kernel, passes) |
| GET | /api/tasks, /api/tasks/{id} | історія / статус, прогрес, ETA |
| POST | /api/tasks/{id}/cancel | скасування |
| GET | /api/tasks/{id}/result | результат |
| GET | /api/admin/stats | статистика (тільки адмін) |

    tests/          pytest

## Стек
